# 输入框建议

每轮任务结束后，用当前会话的模型生成一句「下一步可以做什么」，直接写进输入框的占位文字；按 <kbd>Tab</kbd> 一键填进草稿（只填入，不发送）。

## 它解决什么

长任务收尾时，最难的是判断下一步该干什么：继续跑测试、看 diff、补一个用例，还是收工。这个插件在一轮结束、输入框还空着的时候，把一句具体的建议放到你原本读「发消息或创建任务…」的位置，省掉重新组织语言的那几秒。

## 使用

1. 装好并在 Plugins 页启用后，正常对话即可，不需要额外操作。
2. 一轮结束、草稿为空时，输入框占位文字会替换成建议（通常 1～3 秒内出现）。
3. 想采纳：输入框聚焦时按 <kbd>Tab</kbd>，建议文本填入草稿，可继续修改或直接发送。
   占位文字只有一行（宿主用 `text-overflow: ellipsis` 截断），但 **Tab 填入的是完整建议**，不受可视截断影响。
4. 不想采纳：直接开始输入即可，占位文字随宿主机制自动消失。
5. 人不在这个会话窗口（切到别的会话、最小化、关窗但应用仍在跑）时，Host 会在轮次结束 2 秒后自己生成一份放进缓存；切回来立刻就能看到，不用再等模型。

以下状态**不会**被接管，宿主的原生占位文字保持原样：新会话空白页（hero）、未选择工作区、输入被其它功能锁住、计划模式、有排队插话。

## 配置

在 profile 的 `cordis.patch.yml` 里覆盖 `dsh-suggestion` 这一行的 `config`：

```yaml
- id: dsh-suggestion
  name: '@lixiangzhong/dsh-suggestion'
  config:
    enabled: true
    provider: ''          # 留空 = 跟随该会话最近一次请求的模型
    model: ''             # 与 provider 必须同时给出才生效
    timeoutMs: 8000       # 单次调用超时；超时按「没有建议」处理
    maxChars: 200         # 建议的字符上限（按码点）；占位只显示一行，Tab 给全文
    summaryEnabled: true  # 是否为更早的对话另做一次增量摘要
    summaryMaxChars: 800  # 摘要自身的字符上限
    tracePath: ''         # 诊断用：填一个 JSONL 路径才落盘，默认关闭
```

只配 `provider` 或只配 `model` 视为未配置，插件继续跟随会话模型。

### 排障留痕

需要确认「某次为什么没有建议」时，把 `tracePath` 指向一个文件（例如 `/tmp/dsh-suggestion.jsonl`），插件会把每次请求的结论追加成一行 JSON，来自 Host 与浏览器两半：

- `host/suggest` 的 `outcome`：`generated` / `cached` / `no-turn` / `turn-in-flight` / `stale-turn` / `no-route` / `llm-failed` / `empty-turn` / `subagent` / `aborted`；
- `host/background.attempt`（兜底开始）与 `host/background.cancelled`（客户端取消了兜底）；`llm-failed` 的错误里带上游 code 与 message；
- `client/*`：`client.start`、`hook.changed`（宿主占位钩子是否在、默认文案词典是否读到）、`bridge.mount`、`mount.request`、`request.*`、`paint.applied` / `paint.skipped`、`accept.*`。

兜底生成需要知道界面语言：客户端挂载与切换语言时会 POST 一次 `/dsh-suggestion/locale`，Host 记住最近一次上报；从未上报时退回 `en`。

验证完把 `tracePath` 清空即可，写盘随之停止。更多「改了没生效 / 没看到建议」的排查步骤见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。浏览器控制台还挂了一个只读写插件自身状态的调试入口 `__DSH_SUGGESTION__`（`get` / `set` / `request` / `repaint`）。

## 成本与边界

- 每轮只等**一次**模型调用：早期对话摘要只在建议返回之后于后台增量刷新，不占用户等待时间（首次请求若还没有摘要，直接不带摘要生成，质量损失极小）。
- 每次轮次结束**最多一次**调用：窗口在场且草稿为空时由客户端请求；窗口不在场时由 Host 2 秒后兜底；窗口在场但草稿非空时客户端会发一条取消，Host 不生成。
- 建议在进程内缓存 12 小时（按「会话 + 轮次」分区，**不按语言**）：兜底与客户端可能带着不同语言到达，同一轮只保留一份结果，避免重复调用；进程重启后缓存清空。
- 历史较短（转写 ≤1800 字）时摘要直接用原文，不做额外调用。
- 默认跟随会话模型：在贵模型会话里就会按贵模型计价。想更快更省就把 `provider` / `model` 指向更小更快的模型。
- 送入模型的上下文是收窄过的：用户消息与最终回答各 ≤2000 字、工具摘要 ≤10 行、摘要 ≤800 字——这是首字延迟的主要成本项。
- 同一轮次的结果在进程存活期间复用，多开标签页、刷新、切回会话都不会重复生成。
- 「10 分钟」只约束**首次生成**：切回超过 10 分钟的旧轮次不会再花一次调用，但已有缓存照样返回。
- 模型调用遇到上游错误会**自动重试一次**（超时/取消不重试）；仍失败、没有可用路由等情况一律静默：占位文字保持宿主默认，不弹错误、不写会话日志。
- 子代理会话不生成建议：那里没有「用户下一步」。

## 数据流

浏览器半边在会话 `running` 由 true 变 false 时请求 `GET /dsh-suggestion/suggest?session=<id>&locale=<tag>`；Host 半边读取该会话最后一轮的用户消息、最终回答与工具摘要（必要时附带早期对话摘要），调用 `ctx.llm.stream()` 生成一句话返回。插件不写会话事件、不注册工具、不改模型上下文。

## 已知限制

- 占位文字接管依赖宿主提供的 `data-composer-placeholder` 钩子；DSH 若移除或改名，插件自动降级为输入框下方一行可点击建议条，不会报错，但不再显示在占位里。
- 建议是单行省略号截断的：超过可视宽度的部分会被裁掉，因此提示词要求把动作放在句首。
- 会话摘要只存在进程内：DSH 重启后第一次请求会重新摘要一次（多一次调用）。
- 只处理最后一轮；一轮里多个子步骤的中间过程由工具摘要概括。
